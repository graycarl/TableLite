第 04 章编辑数据

这一章是整个工具里最需要小心的部分。核心只有一句话： 你在界面上做的任何修改都不会立刻写进数据库。 改动先进暂存区，你确认后再一次性提交。

为什么要有暂存区

如果每改一个格子就发一条 UPDATE，那你没有任何反悔的机会—— 手滑改了生产库的一列数据，唯一的补救办法是去翻备份。

把改动先攒起来，能带来三件好处：

  1. 可以预览。提交前能看到将要执行的确切 SQL，确认是改这 7 行而不是那 7 行。
  2. 可以整体放弃。一键回到服务器上的真实数据，什么都不用管。
  3. 要么全成要么全不成。所有改动打包在一个事务里，中间的语句失败就整体回滚，不会留下改了一半的状态。
按钮上的数字

工具栏「提交修改」按钮右边始终显示待提交的改动条数。它是 0 的时候整个按钮组是灰的， 所以「现在有没有没提交的东西」这个问题，扫一眼工具栏就知道。

什么时候能编辑

一张表要能编辑，必须先能被可靠地定位到某一行。不满足条件的表会被明确地置为只读。

表的条件能不能编辑状态栏会说什么
有主键可以—
有唯一索引，且索引列都不可为 NULL可以—
唯一索引的列可以为 NULL不能唯一索引的列可以为 NULL，无法可靠定位行
没有主键也没有唯一索引不能该表没有主键或唯一键，无法安全定位行

不可编辑时的表现
  • 「插入行」按钮直接隐藏，不是变灰
  • 「删除行」禁用
  • 双击单元格改成打开快速查看（内容还是能看全的）
  • 状态栏把原因写清楚，而不是留一堆灰按钮让你猜

改一个单元格

先进入编辑状态

双击单元格，或者选中后按 ↩。编辑器会根据这一列的类型自动选一个合适的：

提交和放弃这次编辑

按键结果
↩提交并退出编辑状态
Tab提交并移到右边一个可编辑单元格
⇧Tab提交并移到左边一个
Esc放弃这次编辑，恢复原值
⇧↩在多行编辑器里换行（不会提交）
校验失败会拦住你

数字列只接受合法数字（含负号和小数点），日期时间列会校验格式。 校验不过时输入框会抖一下并给出提示，编辑状态不退出，你可以直接改。

改完之后界面会告诉你什么

  • 改过的单元格变成橙色底色，左上角出现小三角标记
  • 改过的行，行号列也会出现标记
  • 这些标记一直保留到提交或放弃
  • 如果你把某一格改回原来的值，那个格子的标记会消失；如果一行里所有改动都被改回了，这一行恢复成干净的

插入、复制、删除行

插入行

  • 点状态栏的 + 行，或者按 ⌘I
  • 网格底部出现一条绿色虚线行，光标停在第一个可编辑列
  • 只填需要填的列，留空的交给数据库默认值；自增主键留空即可
  • 没提交之前按 Esc 可以取消这一行

复制行

  • 选中若干行，按 ⌘D，或右键 → 复制行
  • 复制出来的行作为新增行插进来，自增主键会被清空，其余列保留原值
  • 复制出的行立刻进入暂存状态

删除行

  • 选中行按 ⌫，或右键 → 删除行
  • 行立刻变淡加删除线，但还没真正删除
  • 删除前会显示将要执行的条件，例如 WHERE id = 42，让你确认删的是哪一行
  • 已标记删除的行不能再编辑

粘贴

在单元格上按 ⌘V，如果剪贴板里是带制表符或换行的多行文本（比如从 Excel 复制的）， 会从当前单元格开始按二维表格铺开。每一格都走和手工编辑一样的校验；目标列不够时会截断并提示。

暂存区的规则

暂存区属于当前标签。每个表数据标签各有一个，互不影响。切到别的标签不会丢内容。 在同一个标签里，同一行最多只会有一条待提交的改动。

已有新操作结果
无改某列记为「修改」
已改 A 列再改 B 列合并成一次「修改」
已改 A 列把 A 列改回原值这一行的改动消失
无新增行记为「新增」
新增行继续改这一行合并进「新增」
新增行又删除这一行两者都消失，不产生任何操作
无删除行记为「删除」
已改某行又删除该行「修改」被「删除」取代
已删除某行试图编辑该行拒绝，提示先撤销删除

右键某一行 → 撤销该行的修改，可以只回退这一行，别的改动不受影响。

预览

按 ⇧⌘P 或点工具栏「预览」，看看将要执行什么。

预览和实际提交完全一致

面板里显示的语句就是实际会下发的语句，不存在「预览是一套、执行是另一套」的情况。 这一点是刻意设计的：所有写入都直接生成 SQL 文本，不经过参数化改写。

把鼠标移到预览里的某一条语句上，网格里对应的那一行会高亮，方便你确认。

  • 复制全部：把这几条语句拷到剪贴板。
  • 在新查询标签中打开：把这些语句放进一个查询标签，你可以手动调整后再执行。 注意从这里走出去以后就不再走暂存区了，改完直接执行会真的生效。

提交

按 ⌘S 或点工具栏「提交」。提交过程是这样的：

  1. 界面锁定编辑，状态栏显示 正在提交 3/7…
  2. 所有改动在一个事务里依次执行
  3. 全部成功 → 清空暂存区，重新加载当前页，状态栏短暂显示 已提交 7 处修改，耗时 128 ms
  4. 任何一条失败 → 整个事务回滚，所有改动都没生效，弹出错误面板
失败后暂存区不会被清空

提交失败时你的修改原样保留在暂存区，可以修正后再提交。 因为事务已经整体回滚，数据库里什么都没变，所以这时也不需要「回退」什么。

提交过程中的其他规矩

  • 可以取消。取消会在两条语句之间停下来并回滚。
  • 提交超时时会提示：提交超时，事务状态未知，请在数据库中手动核对这几行的数据。 这是少数几个没法自动补救的情况，必须人工确认。
  • 如果待提交内容里混进了结构变更语句（本工具自己不会产生，但可能通过粘贴带进来）， 会直接拒绝，并提示你用 SQL 编辑器执行。

某条语句影响 0 行怎么办

算成功

如果某条 UPDATE / DELETE 影响 0 行（比如这一行已经被别处删掉了）， 视为成功，不报错。Console Log 里会记一条「影响 0 行」， 提交完成后这一行会从刷新后的数据里消失。

这样做是有意的：如果你在改一条别人刚删掉的数据，弹一个错误出来只会打断你， 反正结果（那一行不存在）和你想的一样。

放弃

  • ⇧⌘⌫ 或点工具栏「放弃」：清空整个暂存区并重新加载当前页。
  • 改动超过 5 条，或者包含删除 / 新增时，会先弹窗确认。
  • 只想回退一行：右键那一行 → 撤销该行的修改。
  • 放弃后表格恢复成服务器上的真实数据。

有未提交改动时的保护

下面这些操作会先问你，避免手一滑把攒了半天的改动弄丢：

  • 关闭这个标签
  • 断开或切换连接
  • 重载当前页（⌘R）
  • 应用过滤器或改变排序
  • 退出 App

一个必须知道的限制：不检测并发修改

最后写入者生效

TableLite 不检测「这一行在你打开页面之后是否被别人改过」。 提交时直接用你本地的值覆盖服务器上的当前值。

也就是说：如果你在 10:00 打开一行、10:05 才提交，而别人在 10:02 改过同一行， 那么别人的改动会被你覆盖掉，而且不会有任何提示。

这是刻意的取舍——要检测就得给每张表加版本列或者比对整行原值， 对一个自用工具来说不划算。用在多人同时在写的表上时请自己注意。
