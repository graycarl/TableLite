# 11 · 元数据、CSV 编解码与导出

## 1. 元数据读取（`MetaRepository`）

### 1.1 为什么用 `information_schema` 而不是 `SHOW`

一次查询能拿到全部对象的带排序结果、字段更完整（注释、生成列、`COLUMN_TYPE` 原始文本、字符集）、结果集列名稳定。库列表用 `SHOW DATABASES` 更省事（且只返回有权限的库）。

### 1.2 缓存策略

| 数据 | TTL | 失效时机 |
| --- | --- | --- |
| 库列表 | 会话内不过期 | 重连 |
| 对象列表 | 5 分钟 | `⌘R`、执行 DDL、重连 |
| 表结构 | 5 分钟 | `⌘R`、执行 DDL |
| 行数估算 | 30 秒 | 每次翻页 |

- 执行 SQL 后用词法扫描判断是否包含 DDL 关键字，命中则失效对应表缓存；解析不出表名时保守地失效整个库。
- 系统库过滤（`information_schema` / `performance_schema` / `mysql` / `sys`）由偏好控制。
- 展示类型以 `COLUMN_TYPE`（原始文本）为准，能区分 `tinyint(1)`、`bigint unsigned`、`enum(...)`。

## 2. CSV 编解码

**不引入第三方 CSV 库。**

### 2.1 写

- 需要加引号的字段：含分隔符、含引号、含换行、首尾有空格。引号内的引号用 `""` 转义。
- `NULL` 按配置输出为空串或 `NULL` 字面量；二进制输出为 `0x…` hex。
- 浮点用服务器返回的原始文本，不重新格式化（避免精度丢失）。
- 用缓冲写并定期刷盘，避免大文件占内存。

### 2.2 读

必须覆盖的边界：引号内的分隔符与换行不切分；`""` 还原为一个引号；字段首尾空格**保留**；列数少于表头补空、多于表头报错并给出行号；识别并去掉 BOM；兼容 CRLF / LF / CR；末行无换行仍被读取；空文件报错；引号未闭合报错并给出行号。

### 2.3 编码检测

不引入第三方检测库。顺序：UTF-8 严格解码 → GB18030（覆盖 GBK / GB2312）→ 带 BOM 的 UTF-16 → 都失败则提示用户手动选择（提供常见选项）。

### 2.4 分隔符检测

读前 5 行统计候选分隔符（逗号 / 制表符 / 分号 / 竖线）的出现稳定性；检测失败时用逗号并提示用户确认。

## 3. 导出

只支持 CSV（S9）。字段转义、`NULL` 表示、二进制输出同 §2.1。

### 3.1 流式实现（硬约束）

**导出绝对不能先把数据全读进内存**：用 unbuffered 查询，边收边写。

- 生成查询：表导出带过滤器与稳定排序；结果集导出用原 SQL；选中行导出用行定位键拼 `WHERE`。
- **写临时文件，成功后原子替换目标文件** —— 取消时不会留下看起来完整但实际截断的文件；中断时改名为 `.partial` 并提示文件不完整。
- 定期检查取消并上报进度。

### 3.2 剥掉 LIMIT

从查询结果导出时，尝试剥掉最后一个**顶层** `LIMIT`。若解析不确定（`LIMIT` 在子查询里、含 `UNION`），**不修改 SQL**，并在导出面板明确写出「将导出本次实际返回的 N 行」（L2，宁可少导出不要导错）。

## 4. 导入

- 流程：流式读文件 → 预览前若干行 → 列映射 → 生成 INSERT。
- 批量 `INSERT … VALUES (…), (…)`，每批 500 行（可配）；值走与手工编辑相同的字面量路径与类型校验。
- 类型不匹配：事务模式整体回滚；非事务模式记录失败行并继续，失败行收集前 100 条（原行号 + 原内容 + 错误），完成后可导出为 CSV。
- 从 CSV 新建表：扫前若干行推断列类型（整数 / 大整数 / 小数 / 日期时间 / 变长字符串或文本），列名重复或为空时用 `col_N`；推断结果可逐列修改，执行前展示生成的 `CREATE TABLE`。
