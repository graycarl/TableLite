# 09 · 过滤器

对应 TablePlus 的 Filter（行过滤）与 Column Filter（列过滤）。两者都是**纯客户端状态**，只影响生成的 `WHERE` / `SELECT` 列表，不改动数据。

## 1. 行过滤器

### 1.1 状态模型

一组条件 + 连接方式（AND / OR）+ 是否可见；高级模式用一个原始 `WHERE` 片段替代条件行。

支持的比较：等于 / 不等于、包含 / 不包含、前缀 / 后缀、大小比较、为空 / 非空、区间、枚举列表。

### 1.2 界面

网格上方的一条可折叠横条，每行是「启用勾选 + 列下拉（可搜索）+ 操作符下拉 + 值输入」，支持增删行、切换 AND / OR、切到 Raw SQL、重置、应用。`Esc` 关闭但保留条件。

### 1.3 快速过滤

- 右键列头 → 按此列筛选（加条件并聚焦值输入）。
- 右键单元格 → 按此值筛选 / 排除此值（立即应用）。
- 外键 `↗` → 在新标签打开被引用表并自动加 `pk = 值`。
- 值域已知（`ENUM` / `SET` / `TINYINT(1)`）时值输入变为下拉。

### 1.4 SQL 生成

**硬约束：值一律走 `SQLValueLiteral`，不做任何手工拼接。**

- `LIKE` 的 `%` 与 `_` 必须转义（先转义再交给 literalizer），并显式加 `ESCAPE '\\'`，避免受 `NO_BACKSLASH_ESCAPES` 影响。
- 数字列且值通过严格数字正则时才不带引号；否则一律带引号。
- 每条条件可用括号包起来后按 AND / OR 连接；**不做嵌套括号分组**（S2）。
- 需要值的操作符遇到空输入 → 跳过该条件并在 UI 标黄；`IN` 空列表 → 拒绝并提示。

### 1.5 Raw SQL 模式

- 直接写 `WHERE` 片段；与条件行**互斥**（切换时清空另一侧）。
- 只做「防呆」级检查（如不能含 `;`），**不作为安全边界**（S3）——用户本来就能在编辑器里跑任意 SQL。

### 1.6 持久化

随标签生命周期；可选按「连接 + schema + table」存 UserDefaults，下次打开恢复，默认开启（可在偏好关闭）。

## 2. 列过滤器

- `⌥⌘F` 打开列显隐浮层，带搜索、全选 / 全不选；至少保留一列可见。
- 列显隐**不影响 SQL**，隐藏列仍会被查询（S4）；隐藏的大字段也仍会被截断投影查询，不做优化。
- 列显隐与列宽一起持久化。

## 3. 与分页 / 排序 / 暂存的交互

| 交互 | 规则 |
| --- | --- |
| 应用过滤器 / 改排序 | 重置到第 1 页并重新查询 |
| 有未提交改动时改过滤器 / 排序 | 允许，但提示「修改会保留」；暂存不受影响 |
| 条件引用了不存在的列 | 生成 SQL 前校验，报错并高亮该条件 |
| 过滤器 + 提交 | 提交后按当前过滤器重新查询 |
