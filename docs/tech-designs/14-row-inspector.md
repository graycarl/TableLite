# 14 · 右侧字段栏（行详情栏）

表数据标签里**唯一**的编辑入口。数据网格只读，字段值的查看与修改都发生在这里。
需求见 [`specs/03-data-browsing.md`](../../specs/03-data-browsing.md) §7 与
[`specs/04-data-editing.md`](../../specs/04-data-editing.md) §3。

## 1. 技术选型

用 **SwiftUI** 实现，不进 AppKit：

- 字段数量通常是几十到几百，`LazyVStack` + `ScrollView` 足够，没有十万行的滚动压力。
- 表单式布局用 SwiftUI 更省事。
- 唯一的例外是**长文本 / JSON 的大窗口编辑器**：复用查询编辑器的 AppKit `NSTextView` 组件（需要行号、查找，以及强制关闭智能替换，见 `10-query-editor.md` §2）。

值编辑器直接用 SwiftUI 控件；用 `VStack` 自绘布局（可变行高，多行字段更高），不用 `Form`（会引入系统默认的分组样式与间距）。

## 2. 状态与数据流

网格的「焦点单元格 / 选区」是**唯一真源**，字段栏是它的投影加编辑器。

- 字段栏展示的行 = 焦点单元格所在行。
- 多选 → 不渲染字段列表，提示「请只选一行」；无焦点 → 空状态。
- 切换行时先清空草稿与错误，再触发大字段的按需加载。
- 字段栏自身状态：字段搜索、当前焦点字段、未提交草稿、校验错误、上一次非 NULL 值、正在二次加载的大字段集合。

## 3. 字段编辑器映射

| 列类型 | 控件 |
| --- | --- |
| 普通文本 | 单行文本 |
| 数字 | 单行文本，等宽数字，与其它值一样左对齐 |
| 长文本 / JSON | 内联多行文本（限高）+「展开」到大窗口 |
| 日期 / 时间 | 日期选择器 + 可手输文本 |
| `ENUM` | 下拉 |
| `SET` | 多选 |
| `TINYINT(1)`（偏好开启时） | 三态复选框 |
| BLOB / 二进制 | 不可文本编辑，只提供查看 / 从文件导入 / 设为 NULL |

主键字段列名加钥匙图标并加粗；类型文本只读，来自 `COLUMN_TYPE`（`07-data-grid.md` §3.2）。

## 4. 提交路径

- 编辑器未失焦时值只存在于草稿；**失焦或按 `↩` 才提交**，`Esc` 丢弃草稿。
- 提交时：值未变化 → 丢弃草稿；校验失败 → 保留草稿与编辑状态并显示错误；大字段尚未加载完整值却在其截断值上编辑 → 先加载完整值。
- 成功则写暂存、标脏该行、**增量重绘该行**（不重新查询）。
- 同一行的多次编辑由暂存区合并（`08-pending-changes.md` §2.2）。
- **只有用户实际编辑过的列才进入 `SET`**；未被编辑的截断大字段绝不写回（`08-pending-changes.md` §9）。

## 5. NULL 切换

`∅` 按钮把字段置为 NULL，并记住切换前的值；再点一次恢复。值本身就是 NULL 时按钮呈按下状态。从 NULL 恢复不需要二次加载。

## 6. 大字段的二次加载

- 选中单行且字段栏可见时，字段栏需要完整值；键集合来自行定位键（`08-pending-changes.md` §2），复合主键用 `AND` 连接。
- 是否自动加载由长度列给出的字节数决定：合计 ≤ 阈值（8 MB）→ 选中行后自动加载；超过 → 显示「加载完整内容…」按钮（L12）。
- 结果与 Quick Look 共用同一份缓存；再次选中同一行命中缓存，`⌘R` 清空。
- 行无法定位 → 不发起查询并提示；查询返回 0 行 → 提示「该行已不存在，可能已被删除」。

## 7. 与暂存区、网格的联动

- 字段栏不持有暂存数据；改动落进暂存区后由它反查渲染。
- 字段橙色标记、行状态（干净 / 已改 / 新增 / 已删除）都从暂存区派生，网格与字段栏共用同一份。
- 新增行时字段栏切到「新增行」模式（写新增而非修改）；已删除的行全部只读变灰，并提供「撤销删除」。

## 8. 宽度与持久化

- 宽度存**全局偏好**（一份，切表不重算）；列宽那套「连接 + schema + table + 列名」前缀规则不适用于它（`13-open-questions.md` S21）。
- 默认 300pt，范围 260–560pt；显示状态存全局偏好，默认启用。字段栏只在有选中行（或新增行）时出现，未选中时收起，把宽度还给网格。
- 字段少于等于 10 个时隐藏搜索框；`∅` 按钮固定在字段名行右端的小槽位（始终占位、平时淡灰字形，聚焦加深，`NULL` 时按下态），并在编辑器里显示灰色斜体 `NULL` 占位；值编辑器默认无边框，只有聚焦才出白底与焦点描边。

## 9. 决策记录：字段行的视觉分层

一个字段行分上下两层，而不是「左边名字、右边值」的一行：

- **字段名行**：字段名（小字、次要色、semibold；主键再加粗并带钥匙图标）在左，类型（更淡的小字，只读）在右，`∅` 按钮固定在最右端的小槽位（16pt 宽，平时是淡灰字形，不隐身）。
- **值行**：编辑器独占整行宽度，左缘与字段名对齐。

配套规则：

- 字段之间画 1pt 分隔线（`AppColor.rowSeparator`，**通栏不缩进**，最后一个字段不画）；不再用圆角小卡片 —— 圆角卡片叠加分隔线会打架。
- **整条「面」的底色只表示「已修改」**（橙色淡底 + 小三角），字段行**没有悬停底色**。这条路走过两步：一开始一悬停就同时铺 4% 行底、5% 编辑器底再描一圈边，鼠标扫过时是一片灰带乱闪，而且和「未提交修改」用了同一套视觉语言，容易被读成「这行改过」；缩到 2.5% 定位底 + 指针变文本光标之后仍然觉得多余 —— 字段栏不是可点的列表，「我现在在哪一行」在这里没有意义，索性全部去掉。可编辑的提示只留两处：值上原生就有文本光标，`∅` 那里始终有一个淡灰字形。
- 聚焦也不复制一份整条高亮，交给值编辑器自己的白底与焦点描边：单行走 `@FocusState`，多行由 `PlainTextView` 的 `onFocusChange` 回调提供（`NSTextView` 拿不到 `@FocusState`，漏了它就是「点进去编辑框却完全消失」）。值编辑器的悬停分支已删掉，只有聚焦才换外观 —— 悬停就摆出输入框的样子，看着像已经进入编辑。
- 文字基线统一到**离面板边 12pt**：行内边距 6 + 编辑器内边距 6，字段名行同样补 6pt 前导，标题区也用 12pt。三者对上之后，面板只有一条左缘线（`InspectorMetrics` 的三个常量）。
- 分隔线**通栏**（不缩进），和标题下面那条 `Divider()` 同宽 —— 缩进的分隔线配通栏标题线，会出现两条互不对齐的「边」。
- 主键的钥匙图标内联在字段名之前，所以主键行的名字比其它行多缩进一个图标宽 —— 线框图也是这么画的。
- `∅` 始终在字段名行右端的 16pt 槽位里，只改轻重（淡灰字形 → 聚焦加深 → `NULL` 按下态）。早先是「聚焦 / `NULL` 才现身」，槽位虽然一直占着（类型右缘数学上对齐），但右侧的**视觉停靠线**在「类型末字」和「胶囊右缘」之间摇摆，看上去就是没对齐；改成常显淡字形后右端只有一条线。
- 纵向留白：行上下各 6pt，字段名与值之间 4pt（`AppSpacing.xxs`）；多行编辑器不再写死 `minHeight`（按内容长高，一行内容就一行高）—— 否则空值字段也会撑出两行空白。
- 多行编辑器的高度由 `InspectorFieldHeight`（纯函数 + 单测）按「文本 + 实测宽度」算出来，夹在 1–3 行之间、按整行截断。`NSTextView` 自己不报高度：交给它 `minHeight` 就只有那么高（长文本被压成一行 + 滚动条），用 `NSViewRepresentable.sizeThatFits` 又会让 `NSScrollView` 和 SwiftUI 的行高打架（实测整栏内容互相覆盖）。
- 量高度只采样前 600 个字符：面板允许的最宽 560pt 下这也远超 3 行，而全量 `boundingRect` 对 8 MB 的字段要 1.5 秒 —— 它是 `body` 里的派生属性，每敲一个字都会重跑（AGENTS 坑 §6）。宽度用 `onGeometryChange` 量真实值（窄栏、系统滚动条都算在内），首帧没量到时退回偏好宽度。
- 内联框关掉滚动条（换行滚动靠触控板）；`展开` 在聚焦、只读、或内容超过三行时出现 —— 只读连接里的长文本也得打得开，「展开」按钮本身不参与 Tab 焦点环。快捷键提示只在聚焦时给。
- 行高不再追求与网格行高一致：两层结构加多行编辑器本来就不可能对齐，行高由内容决定（推翻 §1 原先「固定行高」的说法）。
- 所有值左对齐；数字 / 日期时间 / 二进制的数字串只开**等宽数字**（`Font.monospacedDigit()`），不换 `design: .monospaced` —— SF Mono 的左边距比 SF Pro 多约 2pt，换了之后数字值的左缘会比文本值右移，和「统一左缘」直接冲突。字段栏是纵向表单，右对齐的单值在行内没有参照物、只会让左缘参差（网格单元格的右对齐是另一回事，见 `07-data-grid.md`）。
- `∅` 不占值行宽度：值行因此能吃满整宽，左右边缘都齐。

理由：默认 300pt 的窄栏里，「名字 / 类型 / 值」挤在同一行时三者字号字色接近、只能靠间距分辨，多字段纵向排列后又没有分隔，看起来就是一团。上下两层把「标签」与「内容」的层次拉开，分隔线与统一左缘把它组织成表单。
