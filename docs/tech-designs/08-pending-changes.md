# 08 · 变更暂存（Pending Changes）

本项目**最核心**的机制：GUI 上的任何数据修改都不直接落库，而是先进入当前标签的暂存区，用户确认后才以事务形式提交。

## 1. 作用域

- **每个数据网格标签一个独立暂存区**（需求见 [`specs/04-data-editing.md`](../../specs/04-data-editing.md) §8）；Commit / Discard 只影响当前标签。
- 切换到别的标签 / 连接都不会丢失暂存（标签还活着，暂存就还在）。
- 关闭标签 / 关闭 App 时有未提交改动 → 确认弹窗（提交 / 放弃 / 取消关闭）。

## 2. 数据模型

暂存里只有三类变更：新增 / 修改 / 删除，每类都携带行定位与值。

### 2.1 为什么用「原值」定位

提交时 `WHERE` 必须匹配**修改前**的值：

```sql
-- 用户把 id 从 5 改成 6
UPDATE `db`.`t` SET `id` = 6 WHERE `id` = 5;
```

因此行定位键在**第一次编辑该行时就被冻结**，后续再改这一行的其他列不会改变它；同一行的多个编辑合并进同一条修改。

### 2.2 合并规则

同一行最多只有一条 pending change（新增 / 修改 / 删除三选一）：

| 已有 | 新操作 | 结果 |
| --- | --- | --- |
| 修改 | 再改同一行其它列 | 合并 |
| 修改 | 把某列改回原值 | 若不再有改动 → 删除该 change，行状态回到干净 |
| 新增 | 编辑同一新行 | 合并进新增 |
| 新增 | 删除同一新行 | 直接删除该 change，不产生任何 SQL |
| 修改 | 删除同一行 | 替换为删除 |
| 删除 | 编辑该行 | 拒绝，提示先撤销删除 |

## 3. SQL 生成

- **INSERT**：只包含用户在新行里**实际填过**的列；一列都没填时生成 `INSERT INTO t () VALUES ()`，交给服务器默认值。
- **UPDATE**：`WHERE` 用全部行定位键、`AND` 连接，NULL 用 `IS NULL`；`SET` 按列在表中的顺序输出（保证确定性）。
- **DELETE**：`WHERE` 同上。
- 所有值经 `SQLValueLiteral`（`03-mysql-layer.md` §4.2），**Preview 展示的字符串与实际下发的字节完全相同**。

### 3.1 语句顺序

固定为 **INSERT → UPDATE → DELETE**（同类型内按用户操作顺序）。这是刻意简化（S1）：外键约束导致失败时整体回滚，用户自行调整。

## 4. Preview

`⌘⇧P` 打开 sheet，逐条列出将执行的 SQL（带序号与语法高亮），支持复制全部、在编辑器中打开（之后不再走暂存），以及「放弃 / 提交」。

## 5. Commit

1. 暂存为空 → 无操作。
2. 只读连接 → 拒绝。
3. 再次校验所有行定位键非空（防元数据过期）。
4. 在一个事务里**逐条**下发（不用一次性脚本，便于精确定位失败语句）。
5. 任一条失败 → 立即 `ROLLBACK`（尽力），**保留整个暂存不清空**，弹出错误面板（失败序号 + 错误原文 + 该语句 + 「事务已回滚」）。
6. 全部成功 → 清空暂存 → 重新查询当前页。

细节硬约束：

- 提交期间 UI 锁定、显示进度，可取消（在语句之间发 `ROLLBACK`）。
- 不改变会话的 autocommit 设置。
- 含 DDL 的语句提前拒绝并提示用 SQL 编辑器执行。
- Commit 超时 → `KILL QUERY`，并提示「提交超时，事务状态未知，请在数据库中手动核对这几行的数据」。

## 6. Discard

- 清空暂存后**重新查询当前页**（不是简单清脏标记，因为要还原新增 / 删除的行）。
- 支持按行撤销（只回退该行）。
- 改动较多或含删除 / 插入时弹确认。

## 7. 行定位与可编辑性判定

**关键决策**：没有主键的表（不论有没有唯一索引）**整表只读**，不做其它兜底。用户视角的行为见 [`specs/04-data-editing.md`](../../specs/04-data-editing.md) §2。

| 条件 | 结果 |
| --- | --- |
| 有主键 | 可编辑，用主键定位 |
| 没有主键 | 只读 |
| 视图 | 只读 |
| 连接只读 | 只读 |

只读时：隐藏新增按钮、禁用删除、字段栏编辑器禁用并在顶部写明原因（不是简单变灰）、双击单元格改为打开快速查看。

**主键列本身可被编辑**：`WHERE` 用旧值、`SET` 用新值；违反唯一约束时由服务器报错并回滚（L9）。

## 8. UI 元素

- 编辑入口只有右侧字段栏（`14-row-inspector.md`）；工具栏与状态栏只是暂存的只读投影。
- 工具栏按钮：放弃 / 预览(N) / 提交(N)；N 为 0 时全部禁用；只读连接上提交始终禁用并说明原因。
- 标签标题右侧的橙点表示有未提交改动；状态栏显示改动分类统计。

## 9. 边界情况

| 情况 | 处理 |
| --- | --- |
| 提交前表结构被外部改变 | 服务器报错，展示错误，保留暂存 |
| 提交前行被外部删除 | 影响 0 行 → **视为成功**（幂等），Console Log 记录 |
| 提交前行被外部修改 | 直接覆盖（S6） |
| 大字段只加载了截断值、用户只改了别的列 | **截断列不进入 `SET`**，绝不写回 —— 本设计的关键安全保证 |
| 用户编辑截断的大字段 | 先二次加载完整值，在其上应用修改；完整值过大时给出延迟警告 |
| 同一字段反复修改 | 以最后一次为准 |
| 提交时连接已断开 | 尝试一次重连；失败则保留暂存并提示 |
| 事务中服务器崩溃 | 提示「事务状态未知」，不清空暂存 |
