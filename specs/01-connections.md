# 01 · 连接

## 1. 启动界面

App 启动后，如果上次没有留下需要恢复的现场，显示连接列表：

```
┌───────────────────────────────────────────────────────────┐
│  TableLite                                                │
│                                                           │
│  ┌─ 搜索连接… ─────────────────────────────────────────┐  │
│  └────────────────────────────────────────────────────┘  │
│                                                           │
│  ● 本地开发          root@127.0.0.1:3306/app_dev          │
│  ● 预发布            app@10.0.1.5:3306/app_staging        │
│  ● 🔒 生产            app@10.0.2.5:3306/app_prod          │
│                                                           │
│  [ + 新建连接 ]                                           │
└───────────────────────────────────────────────────────────┘
```

- 列表项：颜色圆点 + 名称 + 一行摘要（`用户@主机:端口/数据库`）
- 走 SSH 隧道的连接，摘要里显示 `用户@主机 (经 ssh-主机)`
- 只读连接显示锁图标
- 搜索框按名称与摘要模糊过滤
- **双击**连接项 → 连接并进入工作区
- 右键菜单：`编辑…`、`复制为新连接`、`删除`、`在 Finder 中显示配置文件`

**不做**连接分组，也不做连接的导入导出文件。

### 删除连接

弹窗确认：

```
确定要删除连接「生产」吗？

同时会删除保存在系统钥匙串里的密码。
此操作不可撤销。

[ 取消 ]                                  [ 删除 ]
```

删除后同时清除该连接保存的密码与 SSH 凭据。

## 2. 连接配置表单

用分组卡片纵向排列，避免把字段堆成一屏。

```
┌─ 基本信息 ────────────────────────────────────────┐
│  名称        [ 本地开发                        ]   │
│  颜色        [ ● 绿 ▾ ]      只读  [ ]             │
├─ MySQL ───────────────────────────────────────────┤
│  主机        [ 127.0.0.1    ]   端口 [ 3306 ]      │
│  用户        [ root         ]                      │
│  密码        [ ••••••••     ]   [✓] 保存到钥匙串  │
│  数据库      [ app_dev      ]   （可留空）          │
│  字符集      [ utf8mb4  ▾ ]                        │
│  [ ] 使用 SSL        [ ] 跳过证书校验              │
│  连接超时    [ 10 ] 秒      查询超时 [ 300 ] 秒    │
│  [✓] 保持连接活跃（每 [ 30 ] 秒发送心跳）          │
├─ SSH 隧道 ────────────────────────────────────────┤
│  [ ] 通过 SSH 连接                                 │
│  SSH 主机    [ bastion.example.com ]  端口 [ 22 ]  │
│  SSH 用户    [ deploy             ]                │
│  认证方式    ( ) 使用 ~/.ssh/config 与 ssh-agent   │
│              ( ) 使用私钥  [ ~/.ssh/id_ed25519 ]   │
│              ( ) 使用密码                          │
│  [ ] 使用 ssh config 别名   跳板机 [ user@proxy:22]│
├───────────────────────────────────────────────────┤
│  [ 测试连接 ]                [ 取消 ]  [ 保存 ]    │
└───────────────────────────────────────────────────┘
```

### 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 连接列表里显示的名字 |
| 颜色 | 否 | 用于在界面上区分连接，默认无色 |
| 只读 | 否 | 见 [09-readonly-mode.md](09-readonly-mode.md) |
| 主机 | 是 | 域名或 IP |
| 端口 | 是 | 默认 3306 |
| 用户 | 是 | |
| 密码 | 否 | 可以空着，首次连接时再输入 |
| 保存到钥匙串 | 否 | 默认勾选。不勾选则只在本次运行期间记住 |
| 数据库 | 否 | 可以留空；留空时打开连接后默认选中第一个可访问的库 |
| 字符集 | 否 | 默认 `utf8mb4` |
| 使用 SSL | 否 | 默认开启 |
| 跳过证书校验 | 否 | 仅在服务器使用自签证书时开启 |
| 连接超时 | 否 | 默认 10 秒 |
| 查询超时 | 否 | 默认 300 秒；超时后自动中止查询 |
| 保持连接活跃 | 否 | 默认开启，定期发送心跳避免被服务器断开 |

### SSH 区域的字段

| 字段 | 说明 |
| --- | --- |
| 通过 SSH 连接 | 勾选后下方字段才可用 |
| SSH 主机 | 可以是主机名 / IP，也可以是 `~/.ssh/config` 里的别名 |
| SSH 端口 | 默认 22 |
| SSH 用户 | 登录跳板机的用户名 |
| 认证方式 | 三选一，见下 |
| 使用 ssh config 别名 | 勾上后，完全交给系统 SSH 配置解析该主机（包括别名、端口、用户、密钥） |
| 跳板机 | 形如 `user@proxy:22`，用于「先连 A 再跳 B」的场景 |

认证方式三选一：

1. **使用 `~/.ssh/config` 与 ssh-agent** —— 最省事，完全交给系统处理。已配置过的机器选这个。
2. **使用私钥** —— 手动指定私钥文件路径，需要时输入私钥口令。文件选择器的默认目录是 `~/.ssh`。
3. **使用密码** —— 用 SSH 账号密码登录。密码保存在钥匙串里。

详细的行为规则见 [10-ssh-tunnel.md](10-ssh-tunnel.md)。

### 表单校验

- 主机、用户不能为空
- 端口必须是 1–65535 的整数
- 超时必须是正整数
- 选择「使用私钥」时必须指定存在的文件
- 任何校验失败时，「保存」按钮禁用并在字段下方显示红色提示

### 密码处理

- 编辑已有连接时，密码框回填已保存的密码，显示为圆点
- 密码框旁有「清除已保存密码」按钮
- 首次连接时如果没有密码，弹出输入框，并附一个「记住密码」勾选框
- 「测试连接」成功后才保存密码；测试失败不保存
- 密码绝不出现在界面之外的任何地方（不显示、不导出、不写日志）

## 3. 测试连接

点「测试连接」后，用当前表单里的配置做一次完整探测，结果按步骤展示：

```
┌─ 测试连接 ────────────────────────────────────────┐
│  ✓  SSH 隧道建立成功（127.0.0.1:53142）            │
│  ✓  MySQL 连接成功                                 │
│  ✓  服务器版本：MySQL 8.0.36                       │
│                                                    │
│  [ 关闭 ]                          [ 保存并连接 ]  │
└───────────────────────────────────────────────────┘
```

失败时明确指出是哪一步失败，并原样展示底层错误：

```
│  ✓  SSH 隧道建立成功                               │
│  ✗  MySQL 连接失败                                 │
│     错误 1045：Access denied for user 'root'       │
│     @'localhost' (using password: YES)             │
```

- 测试连接**不检查数据库是否存在**（避免因为库名写错而误判为连接失败）
- 测试用的连接用完立即关闭
- 测试过程可以取消

## 4. 连接状态

每个连接有四种状态，在连接切换器中用图标表示：

| 状态 | 显示 | 说明 |
| --- | --- | --- |
| 未连接 | 灰点 | 保存着但当前没有连接 |
| 连接中 | 转圈 | 正在建立隧道或连接数据库 |
| 已连接 | 绿点 | 正常 |
| 异常 | 红点 | 连接断开或隧道挂了，需要重新连接 |

连接失败时，在连接项上点「查看详情」可以看到：

- 失败发生在哪一步（SSH 隧道 / MySQL 连接）
- 原始错误文本（例如 `Permission denied (publickey).`）
- 建议的排查方向（提示文案见 [12-feedback.md](12-feedback.md)）

## 5. 连接的建立与断开

### 建立连接时依次做什么

界面上依次显示三条进度提示：

1. `正在建立 SSH 隧道…`（未启用 SSH 时跳过）
2. `正在连接 MySQL…`
3. `正在读取服务器信息…`

失败时停在出错那一步，并保留已建立的资源直到用户关闭对话框。

### 断开连接

- 菜单「连接 → 断开连接」，或连接切换器里的「断开」
- 断开前若有未提交的改动，先提示（见 [04-data-editing.md](04-data-editing.md)）
- 断开后该连接的所有标签保留，但内容变灰、显示「已断开」遮罩，点击遮罩可重连

### 自动断开

- 空闲超过 5 分钟且没有任何标签引用该连接时，自动断开以释放服务器连接
- 保活心跳失败时不自动重连，只把状态标为异常并提示用户手动重连

### 重新连接

- 菜单「连接 → 重新连接」（`⇧⌘R`）
- 重连成功后：刷新对象树、重新加载当前标签的数据页
- 重连不会自动重放上次的查询

## 6. 同时保持多个连接

- 可以同时连接多个连接（软上限 8 个）
- 切换连接**不会**断开之前的连接
- 超过 8 个时提示：`同时保持的连接已达上限，请先断开一个不用的连接。`
- 每个连接的标签互不干扰；标签属于它所在的连接，切换连接时显示该连接的标签集合

## 7. 首次启动

一个连接都没有的时候（首次启动，或把连接全删了），显示的就是 §1 那个连接列表在零连接时的样子，不另设欢迎屏：

1. 列表位置显示一句提示：「选择一个连接开始」（与 [02-workspace.md](02-workspace.md) §10 里的空状态是同一句话）
2. 提示下面就是列表里那个 `[ + 新建连接 ]` 按钮（`⌘N`），点它才打开连接配置表单
3. 「测试连接」通过后点「保存并连接」进入工作区
