# 04 · 编辑数据

## 1. 核心原则

**在界面上做的任何修改都不会立刻写到数据库。**

修改先进「暂存区」，用户确认后一次性提交。这样可以在真正落到生产库之前看到会发生什么、也可以随时整体放弃。

提交按钮旁边始终显示待提交的改动条数。

## 2. 可以编辑的前提

行定位只看主键：只有能靠主键可靠定位到某一行时，表数据视图才可编辑。唯一索引不参与判定——有唯一索引但没有主键的表同样不可编辑。

| 条件 | 是否可编辑 | 界面提示 |
| --- | --- | --- |
| 有主键 | 可编辑 | — |
| 没有主键 | 不可编辑 | `该表没有主键，无法安全定位行` |
| 视图 | 不可编辑 | `视图不可编辑` |
| 连接是只读模式 | 不可编辑 | `该连接处于只读模式` |

不可编辑时：
- 隐藏网格底部的 `＋ 插入行` 行（整行隐藏，不是变灰），禁用「删除行」
- 右侧字段栏仍显示字段与值，但所有编辑器禁用，栏顶写明上表里的原因
- 双击单元格改为打开快速查看：非大字段能看全；没有主键的表超长内容仍保持截断（见 [03-data-browsing.md](03-data-browsing.md) §11）
- 状态栏用 [03-data-browsing.md](03-data-browsing.md) §11 的文案写明原因，而不是简单地把按钮变灰

## 3. 在右侧字段栏里改数据

数据网格是**只读**的：不提供在格子里直接编辑。所有字段值的修改都在右侧字段栏里做（字段栏的样子见 [03-data-browsing.md](03-data-browsing.md) §7）。

### 进入编辑

- 点右侧字段栏里某个字段的值；或在网格里双击单元格，会自动切到字段栏里对应的字段并聚焦
- 编辑器按列类型自动选择：
  - 普通文本 → 单行输入框
  - 长文本 / JSON → 多行输入框，可以展开成一个大窗口（带行号与查找）
  - 数字 → 单行输入框，右对齐
  - 日期 / 时间 → 日期选择器 + 手输
  - `ENUM` → 下拉选择
  - `SET` → 多选
  - `TINYINT(1)`（偏好开启时）→ 三态复选框
  - BLOB / 二进制 → 不允许直接改文本；只能「从文件导入」「查看」「设为 NULL」

### 提交这次编辑

- **失去焦点或按 `↩`** 就把值写进暂存区
- `Tab` / `⇧Tab` 提交并移到下一个 / 上一个字段
- `Esc` 放弃这次编辑，恢复原值
- 多行编辑器里 `⇧↩` 换行，`⌘↩` 提交

### 把字段设为 NULL

每个字段右侧有个 `∅` 按钮：

- 点一下把该字段设为 `NULL`，再点一下恢复到原来的值
- 字段本来就是 `NULL` 时，按钮呈按下状态
- `NULL` 与空字符串是两个不同的值，字段栏里分别显示为灰斜体 `NULL` 和一格空白

### 校验

- 数字列只接受合法数字（含负号与小数点）
- 日期 / 时间列校验格式
- 校验失败时输入框抖动并显示提示，保持编辑状态不退出，值不写入暂存区

### 外观反馈

- 修改过的字段在字段栏里变成橙色底色，左上角出现小三角标记
- 网格里对应的单元格也变橙色，修改过的行的行号列出现标记
- 这些标记一直保留到提交或放弃

### 改回原值

把某个字段改回原来的值，这个字段的修改标记自动消失；如果一行的所有修改都被改回，这一行恢复为「干净」状态。

## 4. 插入行

- 点网格底部的 `＋ 插入行` 行，或按 `⌘I`
- 网格底部出现一条绿色虚线行（位置在 `＋ 插入行` 行上方），同时右侧字段栏切换到「新增行」模式
- 光标停在字段栏的第一个可编辑字段上，按 `Tab` 往下依次填
- 只填需要填的列，留空的列交给数据库默认值
- 自增主键列留空即可，提交后由数据库生成
- 未提交前可以按 `Esc` 取消这一行

## 5. 复制行

- 选中若干行，按 `⌘D` 或右键 `复制行`
- 复制出来的行作为新增行插入，主键列（自增的）会被清空，其余列保留原值
- 复制出的行立刻进入暂存状态，字段栏切到这一行，可以直接接着改

## 6. 删除行

- 选中行按 `⌫`，或右键 `删除行`
- 行立即变淡并加删除线，**但还没真正删除**
- 删除前会显示将要执行的条件，例如 `WHERE id = 42`
- 已标记删除的行不能在字段栏里编辑，字段全部变灰；想编辑要先撤销删除

## 7. 粘贴

- 在右侧字段栏的某个字段上 `⌘V`：把剪贴板里的纯文本作为这一个字段的值贴进去，然后走与手工编辑相同的校验
- 网格上**不再**支持把带制表符 / 换行的多行文本铺开成二维表格（网格只读）；需要批量改数据时用 SQL 编辑器

> 只保留单字段粘贴是刻意简化，已登记在 `docs/tech-designs/13-open-questions.md` 的 S14。

## 8. 暂存区的规则

暂存区属于**当前标签**，每个表数据标签各自独立。

- 切换到别的标签不会丢失暂存内容
- 同一个标签内，同一行最多只会有一条待提交的改动
- 累积规则：

| 已有 | 新操作 | 结果 |
| --- | --- | --- |
| 无 | 改某列 | 记为「修改」 |
| 已改 A 列 | 再改 B 列 | 合并为一次「修改」 |
| 已改 A 列 | 把 A 列改回原值 | 这是行的改动消失 |
| 无 | 新增行 | 记为「新增」 |
| 新增行 | 继续改这一行 | 合并进「新增」 |
| 新增行 | 又删除这一行 | 两者都消失，不产生任何操作 |
| 无 | 删除行 | 记为「删除」 |
| 已改某行 | 又删除该行 | 「修改」被「删除」取代 |
| 已删除某行 | 试图编辑该行 | 拒绝，提示先撤销删除 |

- 右键行 → `撤销该行的修改`，可以只回退一行

## 9. 预览

按 `⇧⌘P` 或点工具栏「预览」，打开一个面板：

```
┌─ 将要执行的 SQL（7 条）────────────────────────────────┐
│  1   INSERT INTO `app_dev`.`users` (`name`)             │
│      VALUES ('张三');                                    │
│  2   UPDATE `app_dev`.`users` SET `email`='a@b.c'       │
│      WHERE `id` = 42;                                    │
│  3   DELETE FROM `app_dev`.`users` WHERE `id` = 7;       │
│  …                                                       │
├─────────────────────────────────────────────────────────┤
│  [复制全部]  [在新查询标签中打开]      [关闭]  [提交]    │
└─────────────────────────────────────────────────────────┘
```

- 面板里显示的语句与实际提交的**完全一致**，不会有差异
- 语句按类型分组排序：先插入、再修改、最后删除
- 「在新查询标签中打开」把这些语句放进一个查询标签，用户可以手动调整后再执行（此时不再走暂存区）
- 鼠标悬停在某条语句上时，网格里对应的行会高亮

## 10. 提交

按 `⌘S` 或点工具栏「提交」。

提交过程：

1. 界面上锁定编辑，状态栏显示 `正在提交 3/7…`
2. 所有改动在**一个事务**里执行
3. **全部成功** → 清空暂存区，重新加载当前页，给一条轻提示 `已提交 7 处修改 · 128 ms`（轻提示的形态与文案规范见 [12-feedback.md](12-feedback.md) §3）
4. **任何一条失败** → 整个事务回滚，**所有改动都未生效**，弹出错误面板

失败面板：

```
┌─ 提交失败 ──────────────────────────────────────────┐
│  第 3 条语句执行失败                                 │
│                                                      │
│  [错误 1062] SQLSTATE 23000                          │
│  Duplicate entry 'a@b.c' for key 'uniq_email'        │
│                                                      │
│  DELETE FROM `app_dev`.`users` WHERE `id` = 7;       │
│                                                      │
│  事务已回滚，你的修改都还在暂存区里，尚未生效。      │
│                                                      │
│  [ 放弃全部修改 ]                    [ 关闭并修正 ]  │
└──────────────────────────────────────────────────────┘
```

提交失败后**暂存区不会被清空**，用户可以修正后重试。

### 提交过程中的其他规则

- 提交可以取消（在两条语句之间回滚）
- 提交超时后提示：`提交超时，事务状态未知，请在数据库中手动核对这几行的数据`
- 暂存区内容只由本工具的编辑操作生成，正常不会包含结构变更语句；提交前仍做一次防御性检查，若发现 `INSERT` / `UPDATE` / `DELETE` 以外的语句，直接拒绝并提示改用 SQL 编辑器执行

### 影响 0 行的情况

如果某条 `UPDATE` / `DELETE` 影响 0 行（比如这行已经被别处删掉了）：

- **视为成功**，不报错
- 在 Console Log 里记录 `影响 0 行`
- 提交完成后该行会从刷新后的数据里消失

## 11. 放弃

- `⇧⌘⌫` 或点工具栏「放弃」：清空整个暂存区并重新加载当前页
- 改动超过 5 条，或包含删除 / 新增时，先弹窗确认
- 右键单行 → `撤销该行的修改`：只回退这一行
- 放弃后表格恢复成服务器上的真实数据

## 12. 有未提交改动时的保护

分两种处理：

**会先弹窗询问（三选一：`提交` / `放弃` / `取消`）**：

- 关闭这个标签
- 断开或切换连接
- 退出 App

**不打断操作，只在状态栏提示，暂存原样保留**：

- 重载当前页（`⌘R`）
- 应用过滤器或改变排序

```
┌─ 有未提交的修改 ────────────────────────────────┐
│  当前标签有 7 处未提交的修改。                   │
│                                                  │
│  [ 取消 ]   [ 放弃修改 ]      [ 提交并继续 ]     │
└──────────────────────────────────────────────────┘
```

## 13. 并发修改

- 本工具不检测「这一行是否已被别人改过」
- 提交时直接以本地的值覆盖（最后写入者生效）
- 这一取舍记录在 [00-scope.md](00-scope.md) 的范围内，属于已知限制
