# 09 · 只读模式

## 1. 为什么需要

本工具没有 TablePlus 那种「每次写操作都要求输入数据库密码」的保护，误改生产库的风险仍然存在。一个更轻量的替代方案是：把生产连接的编辑能力整个关掉。

## 2. 开关位置

在连接配置表单的「基本信息」里：

```
名称   [ 生产                       ]
颜色   [ ● 红 ▾ ]      只读  [✓]
```

也可以在打开连接后随时切换：菜单「连接 → 只读模式」。

## 3. 视觉标识

只读连接在界面上有明确标识：

| 位置 | 表现 |
| --- | --- |
| 连接列表 | 名称前显示锁图标 🔒 |
| 连接切换器 | 同上 |
| 工具栏颜色带 | 用连接颜色着色（生产建议设红色） |
| 状态栏 | 连接信息末尾追加 `· 只读`，并用醒目颜色 |
| 标题栏 | 显示 `连接名（只读）` |

## 4. 哪些操作被禁止

### 表数据视图

- 不能编辑单元格
- 不能插入、复制、删除行
- 「提交」按钮禁用（鼠标悬停提示 `该连接处于只读模式`）
- 「放弃」按钮仍可用（如果之前积累过改动）
- 双击单元格改为打开快速查看

### SQL 编辑器

执行前检查每条语句的类型，只允许：

- `SELECT`
- `SHOW`
- `EXPLAIN` / `DESCRIBE` / `DESC`
- `WITH` 开头的查询（前提是最终是查询而不是写操作）

以下一律拒绝：

- `INSERT` / `UPDATE` / `DELETE` / `REPLACE`
- `CREATE` / `ALTER` / `DROP` / `TRUNCATE` / `RENAME`
- `GRANT` / `REVOKE`
- `LOAD DATA`
- `CALL`（存储过程可能内部写数据）
- `SET`（可能改变会话状态影响语义）
- `LOCK` / `UNLOCK`

拒绝时的表现：

```
┌─ 只读模式 ──────────────────────────────────────────┐
│  语句 3 被拒绝执行：                                 │
│                                                      │
│  UPDATE users SET name = 'x' WHERE id = 1;          │
│                                                      │
│  当前连接处于只读模式，只能执行查询语句。            │
│  如需修改，请在连接菜单中关闭只读模式。              │
│                                                      │
│  [ 关闭 ]                                            │
└──────────────────────────────────────────────────────┘
```

混合脚本中的处理：

- 安全的语句正常执行并有结果标签
- 被拒绝的语句在结果标签里标红，标签文字是 `只读拦截`
- 脚本里被拒绝的语句**不会**中断后续安全语句的执行

### 其它

- 对象树的 `截断表`、`删除表` 直接禁用
- CSV 导入功能禁用（导入到新表也禁用）
- 表结构视图里所有入口本来就是只读的，不受影响

## 5. 提示文案

进入只读连接时，状态栏显示一条短暂的提示：

```
该连接处于只读模式，所有写操作已被禁用。
```

工具栏的 `提交` 按钮禁用时，鼠标悬停的提示：

```
该连接处于只读模式，无法提交修改
```

SQL 编辑器的工具栏在只读模式下显示：

```
只读模式：仅允许 SELECT / SHOW / EXPLAIN / DESC
```

## 6. 关闭只读模式

- 菜单「连接 → 只读模式」取消勾选
- 取消后立即生效，无需重连
- 取消时给一次轻确认（避免手滑）：

```
确定要关闭「生产」的只读模式吗？

关闭后可以修改数据、执行写操作。
```

- 该状态保存在连接配置里，下次打开连接仍然生效

## 7. 已知限制

- 只读模式只做**语句级别的拦截**，不是数据库权限控制。真正的安全边界应该由数据库账号权限保证（给这个连接配一个只有 `SELECT` 权限的账号）
- 存储过程 / 函数内部的行为无法拦截，所以 `CALL` 一律拒绝
